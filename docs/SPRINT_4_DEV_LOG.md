### 💡 2. Educational Insights: Under the Hood

#### A. Why We Chose Gemini 3.1 Flash-Lite for Voice
* When designing voice assistants, latency is king. Any turn latency over $1\text{ second}$ feels sluggish and unnatural.
* **`gemini-3.1-flash-lite`**:
  * Optimized specifically for high-throughput, low-latency reasoning and tool routing.
  * Real-world Time-To-First-Token (TTFT) on Google Cloud infrastructure is $\approx 180\text{–}250\text{ ms}$.
  * Combined with our local Piper TTS sentence streamer ($\approx 150\text{ ms}$), total time from when the user stops speaking to when the assistant speaks back is **under $500\text{ ms}$**!

#### B. The Spoken Output Sanitation Problem
* LLMs are heavily trained on Markdown formatting (e.g. using `**bold**`, `*italics*`, bullet lists `- item`).
* If an LLM returns `Here are 3 options:\n* Option A\n* Option B`:
  * A traditional TTS engine pronounces: *"Here are three options, asterisk, option A, asterisk, option B."*
  * This completely ruins the user experience!
* By pairing a strong system prompt (*"Never output markdown symbols in voice conversations"*) with deterministic client-side cleaning (`clean_for_speech`), we guarantee that only natural spoken prose reaches the audio synthesizer.
